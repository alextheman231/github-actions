This is a new patch release of the `github-actions` package. It includes small, non-breaking changes and should require no refactoring. Please read the description of changes below.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Use the GitHub CLI to create the GitHub release rather than the external composite action
  - It's generally better to prefer using native GitHub composite actions/their own API where possible as it reduces the chance of an external composite action potentially getting compromised and also having access to the GitHub token.
    - Although in our case it's not as bad if it did in our setup given the GitHub app usage with a short-lived token. But I still think it's good to do this to minimise the risk as much as possible.
  - In the case of creating a GitHub release, doing it with the GitHub API actually makes the code a little cleaner as well so I think this is the better approach regardless.

## Additional Notes

- Eventually I think it would be nice to replace all our usage of the `peter-evans` composite actions with either our own ones or direct GitHub API usage.
- It would allow us to properly own more of our GitHub integrations and make the workflows a little more secure by removing a dependency on an external workflow that also has access to a potentially sensitive GitHub token.
- It's not as big a priority, though, given that the token we pass to composite actions is short-lived anyway, but it would be good to do at some point to minimise the risk further.
