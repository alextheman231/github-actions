# v13.0.0 (Major Release)

<!-- alex-c-line-release-status-start -->
**Status**: Released
<!-- alex-c-line-release-status-end -->

<!-- alex-c-line-release-summary-start -->
This is a new major release of the `github-actions` package. It has the potential to introduce breaking changes that may require a large amount of refactoring. Please read the description of changes and migration notes below for more information.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Rename the `APP_ID` input/secret to be a `CLIENT_ID` input in all reusable workflows that take it.
  - It more naturally invites the user to pass in the app's client ID rather than the app ID (although in theory both work just fine).
  - It also moves the variable from a secret to a regular input variable where appropriate as it's not really a secret.

## Migration Notes

Before:

```yml
jobs:
  update-dependencies:
    uses: alextheman231/github-actions/.github/workflows/update-dependencies.yml@v12.10.2
    secrets:
      APP_ID: ${{ vars.ALEX_UP_BOT_APP_ID }}
      APP_PRIVATE_KEY: ${{ secrets.ALEX_UP_BOT_PRIVATE_KEY }}
    with:
      update_pnpm: true
      update_javascript_dependencies: true
      update_actions: true
      node-version: 26
```

After:

```yml
jobs:
  update-dependencies:
    uses: alextheman231/github-actions/.github/workflows/update-dependencies.yml@v13.0.0
    secrets:
      APP_PRIVATE_KEY: ${{ secrets.ALEX_UP_BOT_PRIVATE_KEY }}
    with:
      CLIENT_ID: ${{ vars.ALEX_UP_BOT_CLIENT_ID }}
      update_pnpm: true
      update_javascript_dependencies: true
      update_actions: true
      node-version: 26
```

## Additional Notes

- I know, it's literally one single breaking change and suddenly we're on v13.
- Unfortunately there is no deprecated tag for reusable workflows as far as I'm aware, and given that the reusable workflows are mainly used by me anyway and the migration is fairly straightforward I think I am fine with this leap.
