**Status**: Released

This is a new minor release of the `github-actions` package. It introduces new features and other backwards-compatible changes that should require little to no refactoring. Please read the description of changes below.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Move the composite TypeScript actions into this repository
  - This should make it easier to test these, as they can now be tested directly from the reusable workflows themselves. This is now possible to do with the introduction of the self-repository (`$`) syntax.

## Additional Notes

- Well, I guess someone at GitHub read release note v4.0.3 of this repository and actually addressed my complaint there!
- Or, well, to be fair, I doubt they actually saw that release note specifically and actioned that. I think this has probably been something that has been known to be a pain point for some time now, where referencing a local composite action in a reusable workflow was a bit awkward.
- I won't repeat everything I said in that release note, you can [read it for yourself](https://github.com/alextheman231/github-actions/blob/main/docs/releases/v4/v4.0/v4.0.3.md) if you want, but it was very awkward, and it was the main reason I separated the TypeScript Actions into its own repository initially (because we wouldn't be able to reference them locally from here anyway).
- In any case, now that the syntax is here, it is nice to have all the GitHub Actions-related stuff in one place now, and I am very glad that one of my biggest GitHub Actions complaints has actually been addressed. Credit where credit's due!
- Granted, I probably have a lot more actions-related complaints that I still would like to be addressed (most notably the lack of lockfile for actions), but at least they've addressed quite possibly the most awkward one, which is nice.
